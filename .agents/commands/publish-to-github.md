# publish-to-github

Publish the Cook & Bake Academy website from this repository to `alfredang/cnbacademy` and verify its GitHub Pages deployment. Use the repository root containing `dist/`, `README.md`, and `.github/workflows/deploy-pages.yml`. Treat this file as a project runbook; never assume a command is safe merely because it is listed here.

1. **Inspect the release.** Confirm the selected Git repository, `origin` URL, current branch, working tree, GitHub authentication, and the exact files that changed. Fetch `origin/main` and reconcile changes without force pushing. Keep generated archives, browser captures, credentials, and unrelated files out of the commit.
2. **Update the README.** Keep a useful overview, HTML/CSS/JavaScript badges, local installation instructions, architecture, limitations, and the verified live link `https://alfredang.github.io/cnbacademy/`. Describe the course finder accurately as local keyword matching. Do not claim that proposed course fees are verified sales or that the static site has a booking backend.
3. **Review GitHub Pages.** Keep a workflow in `.github/workflows/` that triggers on `main` and manual dispatch, grants `contents: read`, `pages: write`, and `id-token: write`, and uploads only `dist/` with `actions/upload-pages-artifact` before `actions/deploy-pages`. Read GitHub's current documentation before changing action versions. Check Pages settings and select the GitHub Actions publishing source if it is not already configured.
4. **Scan before upload.** Run a current Gitleaks scan on Git history and the working directory, with secret values redacted. If Gitleaks is absent, obtain it from its official release with checksum verification or use an equivalent dedicated secret scanner. Inspect the staged path list and diff. Check for `.env` files, private keys, tokens, credentials, and personal data. Resolve every finding before pushing; do not print or upload secret values. If a dedicated scanner cannot run, report the limitation and stop before publishing.
5. **Publish only reviewed files.** Stage explicit intended paths, run `git diff --cached --check`, review `git diff --cached --stat` and names, commit with a descriptive message, and push `main` to `origin` without force. Never use `git add -A` as a shortcut.
6. **Update repository About.** Set a concise, factual description and the GitHub Pages homepage URL using an authenticated GitHub tool. Read the metadata back. Preserve unrelated repository settings.
7. **Verify the result.** Confirm the remote `main` SHA matches the local commit, the Pages Actions run succeeded, the Pages URL serves the expected site, and `data/courses.json` loads. Report the commit, workflow run, live URL, security scan scope/result, and any remaining limitations. Do not claim success from a queued run.
